# Plan: moving to TypeScript

Status: steps 0 and 1 approved and built locally (2026-10-29). Later steps are decided one at a time.

Goal: catch mistakes before they reach users, starting with the part where a mistake costs the most:
the encryption. Nothing here changes how the app looks or behaves.

## Principles

1. **Small steps, each one shippable.** After every step the app works and CI is green. No big rewrite.
2. **Crypto first.** A bug there can make messages unreadable for good, and TypeScript plus fixed test
   vectors protects exactly that.
3. **Same output.** The new code must read everything the old code wrote, and the other way around.
4. **Nothing is published without an explicit yes** (as today).

## Step 0 - Tooling (no app change)

- Add `typescript` and `esbuild` as dev dependencies, `tsconfig.json` with `strict: true`.
- `npm run build` first compiles TypeScript, then runs `app/build.py` as today. The result is still one
  `index.html`, so GitHub Pages and the tests do not change.
- CI also runs `tsc --noEmit`.

## Step 1 - Crypto module (`src/crypto.ts`)

Move out of `main.js`, with types: identity creation (`makeIdentity`, `fpOf`), shared chat key
(`pairKey`, `aesFrom`), `seal`/`open` for messages, reactions and files, recovery code
(`newCode`, `normCode`, `codeKey`, `makeBackup`, `restoreFromCode`), device transfer (`ephPair`).

Safety net, built before anything is moved:
- **Fixed test vectors:** a fixture file with keys, codes, ciphertext and expected plaintext, generated by
  the *current* code. The TypeScript module must decrypt every fixture and produce ciphertext the old code
  can decrypt. This is what proves nothing breaks for existing users and messages.
- Unit tests for the module run in Node (Web Crypto exists there), so they are fast.

Done when: `main.js` imports the module, the old functions are gone, fixtures and all browser tests pass.

## Step 2 - Language file

Move all user-visible Norwegian text to `src/i18n/nb-NO.ts` (typed keys). Needed anyway before an English
version. The SQL error messages are shown to the user as they are (the client does not parse them), so they stay
in the database for now; for an English version they become error codes that the client maps to texts here.
Tests fail if the app uses a text key that does not exist or if a key is unused.

Progress: the mechanism (`src/i18n/`, `tr("key",{params})`) and all notifications and thrown errors in
`main.js` and `crypto-glue.js` are moved. Rounds 2 and 3 moved the privacy and help dialog and the labels, headings and status texts in `main.js`. Round 4 moved the sign-in and key screens (now a normal source file, `app/views.js`, instead of being cut
out of the old base file by `build.py`) and the static page text in `body.html` (written as `{{key}}` and filled
in by `build.py`). Round 5 moved the last texts (figure names, typing line, error prefixes, page title, boot error). A scan of the built page finds no
Norwegian text left outside the language file; the old base file `app/base/messenger.html` had none in the parts that are used.
Step 2 is done.

Step 1 follow-up (2026-10-30): file encryption (`encryptBytes`/`decryptBytes`), the safety number (`safetyNumber`) and the invite
hash (`inviteHash`) moved into `src/crypto.ts`. `main.js` no longer calls `crypto.subtle` at all. New fixtures for them were made
from the old expressions before the move; `tests/img.js` sends an image between two users end to end.

## Step 3 - Backend access layer

One typed module for every Supabase call (tables and `rpc` functions), with types written by hand from the
database schema. Replaces calls spread around `main.js`.

Progress (2026-10-30): round 1 moved the 15 server-function (`rpc`) calls into `src/api.ts` (`createApi`, one typed function
per database function). `tests/api-unit.js` checks every call against the SQL in `supabase/migrations/` and fails if the app calls
`sb.rpc()` directly. Round 2 moved sign-in and sign-out (`sb.auth`: sign up, password, e-mail code, session, auth-state listener) into the same module; the test
checks the arguments that reach `supabase.auth` and forbids `sb.auth` in the app. `doLogout()` keeps its fallbacks. Round 3 moved the rest: all table calls (`from`), encrypted-file storage, the link-preview edge function and the live channel. After it
the app never touches the Supabase client except to create `api` in `main.js`. The test checks every table and column against the SQL,
the bucket name, the channel name and the tables it listens to, and forbids `sb.` anywhere in the app. Step 3 is done.
The types are written by hand and checked by that test; they are not generated (no Supabase CLI in the build environment).

## Step 4 - The rest of the code, round by round

Agreed 2026-10-30 (rollback tag `rollback-before-step4` = faf99e4, the state checked by Dan Joakim in the app).
Sound, emoji tables, avatar helpers and 133 lines of CSS are not normal source files: they are cut out of the old
prototype `app/base/messenger.html` or live as strings in `build.py`, which patches them with 18 `replace` calls. That has to go
first, or nothing there can be typed.

  shrunk under 3 MB and still animated, fake GIF rejected), `tests/sound.js` (message sound and double ping rendered offline and
  measured), `tests/nudge.js` (double ping really shakes the window, banner, flash, title blink, fires once). No app change.

  and `app/base/` is deleted (this is old step 5, done first). The built `index.html` is byte-identical to the one before; `build.py` has no
  `replace` patching of legacy code left. The "why" comments that lived in `build.py` moved into the files as `//#` notes.
- **Round 2 (done):** emoji codes and conversion are `src/emoji.ts` (bundled as `PrekEmoji`; `app/emoji.js` only gives the old names).
  Locked by `tests/fixtures/emoji-vectors.json` (made by the old JavaScript: all tables, both regular expressions, 775 texts) and
  `tests/emoji-unit.js`; `tests/emo.js` also checks the built page. Checked once by hand: `linkify()` output with animated figures is
  identical before and after on all 775 texts.
- **Round 3 (done):** avatar helpers are `src/avatar.ts` (`okAv`, `toAvatar`, `hue`, `avEl`; bundled as `PrekAvatar`). `okAv` and `hue`

  the centered 64x64 crop and the whole choose-a-picture flow in a browser. Compared once by hand against the old build in a browser:
  identical elements and a byte-identical JPEG. A pre-existing bug was found (a name that starts with an emoji got half a character as its initial) and fixed in a separate commit
  at Dan Joakim's request: `initial()` takes the first whole character (also used for the profile picture slot in the main window).
- **Round 4 (done):** the GIF encoder (`gifQuant`, `gifLzw`, `gifEncode`), `readGif` and `GIF_MAX` are `src/gif.ts` (bundled as `PrekGif`).

  SHA-256 of every output, full file when small) and `tests/gif-unit.js`; `tests/gif.js` still sends GIFs end to end.
- **Round 5 (done):** image and GIF shrinking in the browser is `src/shrink.ts` (bundled as `PrekShrink`, glue `app/shrink.js`). No fixture from the old code is possible (canvas and ImageDecoder), so `tests/shrink.js` locks the behavior in the built page: it passed against the old JavaScript first and then against the TypeScript, and mutations (size, white background, quality steps, frame skipping, delays, limits) are caught.
- **Round 6 (done):** the sounds are `src/sound.ts` (bundled as `PrekSound`; every function takes the audio context). `app/sound.js` keeps the
  shared `AC`, the first-touch start, the old names and `stor()` (shakes the window). The unused old `tone()` was dropped.
  `tests/sound-unit.js` compares every call on a recording audio context (oscillators, frequencies, envelopes, connections, times) with
  `tests/fixtures/sound-vectors.json`, made by the old JavaScript; `tests/sound.js` still renders and measures in a browser and `tests/nudge.js` checks the shake.
  Seven deliberate changes to the numbers were all caught.
- **Round 7 (done):** links and link previews are `src/links.ts` (`cutUrl`, `okHttp`, `firstUrl`, `splitLinks`, `validLk`, `thumb`, `fetchPreview`; bundled as
  `PrekLinks`). `app/links.js` keeps what touches the page: `linkify()` (builds the elements from `splitLinks`), `lkCard()`, the `LP_ON()` setting.
  There was no test for links before, so `tests/links.js` (two users: preview card, setting off, failing and slow preview, shrunk picture, hostile preview
  from the sender, several links) was written first and passed against the old code. `tests/links-unit.js` compares the pure functions with
  `tests/fixtures/links-vectors.json` (made by the old code: 61 texts, 33 link cards incl. the exact 2000 and 90000 character limits). Thirteen deliberate changes were caught.
- **Round 8 (done):** the logic behind reactions is `src/reactions.ts` (`loadReactions`, `groupReactions`, `applyReaction`, `reactionPayload`, `menuPosition`;
  bundled as `PrekReactions`). `app/reactions.js` gives `loadReacts()` its old name and passes in the api call, the decryption and the list of kinds (`RX_OK`,
  which stays in `main.js` next to the texts). `tests/rx.js` only printed things, so `tests/reactions.js` (two users: choose, same kind counts 2, replace, remove,
  order, ciphertext only, moved/forged/unknown/wrong-type reactions ignored, menu inside a narrow screen) was written first and passed against the old code.
  `tests/reactions-unit.js` compares `loadReactions` with `tests/fixtures/reactions-vectors.json` (made by the old code: 27 situations). Of 14 deliberate changes, 12 were
  caught; the other two (`""` and non-text kinds) are double checks that cannot change the result because neither is ever in the list of valid kinds.
- **Round 9 (done), the foundation, part 1:** the page helpers `$`, `el`, `toast`, `fail` and `q` are `src/dom.ts` (bundled as `PrekDom`; `app/dom.js` gives

- **Round 10 (done), the foundation, part 2:** the state `S` is typed. `src/state.ts` describes every field once (`AppState`: 26 that exist from the start,

- **Round 11 (done), logic out of the screens, part 1:** the short texts about a chat are `src/previews.ts` (`PrekPreviews`, glue `app/previews.js`): `previewText` (what the list calls the last message; the rule was written out twice in `main.js`), `listLine` (shortened, with "Du: ") and `pageTitle`. `tests/previews-unit.js` compares with `tests/fixtures/previews-vectors.json` (made from the old inline code: 640 raw messages, 33 decoded, 25 list lines, 9 titles). 10 of 10 deliberate changes caught.

after publishing. Rollback is the previous commit (or the tag).

## Risks

- Subtle encoding differences (base64, JSON key order in the fingerprint) -> covered by the vectors.
- Bundler output differing between browsers -> existing browser tests, plus a manual check on the phone.
- Time: Step 1 is small (about a day of work); Step 4 is the long one and optional.
