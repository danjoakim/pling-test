# Plan: moving to TypeScript

Status: steps 0 and 1 approved and built locally (2026-10-29). Later steps are decided one at a time.

Goal: catch mistakes before they reach users, starting with the part where a mistake costs the most:
the encryption. Nothing here changes how the app looks or behaves.

## Principles

1. **Small steps, each one shippable.** After every step the app works and CI is green. No big rewrite.
2. **Crypto first.** A bug there can make messages unreadable for good, and TypeScript plus fixed test
   vectors protects exactly that.
3. **Same output.** The new code must read everything the old code wrote, and the other way around.
4. **Nothing is published without an explicit yes** (as today).

## Step 0 - Tooling (no app change)

- Add `typescript` and `esbuild` as dev dependencies, `tsconfig.json` with `strict: true`.
- `npm run build` first compiles TypeScript, then runs `app/build.py` as today. The result is still one
  `index.html`, so GitHub Pages and the tests do not change.
- CI also runs `tsc --noEmit`.

## Step 1 - Crypto module (`src/crypto.ts`)

Move out of `main.js`, with types: identity creation (`makeIdentity`, `fpOf`), shared chat key
(`pairKey`, `aesFrom`), `seal`/`open` for messages, reactions and files, recovery code
(`newCode`, `normCode`, `codeKey`, `makeBackup`, `restoreFromCode`), device transfer (`ephPair`).

Safety net, built before anything is moved:
- **Fixed test vectors:** a fixture file with keys, codes, ciphertext and expected plaintext, generated by
  the *current* code. The TypeScript module must decrypt every fixture and produce ciphertext the old code
  can decrypt. This is what proves nothing breaks for existing users and messages.
- Unit tests for the module run in Node (Web Crypto exists there), so they are fast.

Done when: `main.js` imports the module, the old functions are gone, fixtures and all browser tests pass.

## Step 2 - Language file

Move all user-visible Norwegian text to `src/i18n/nb-NO.ts` (typed keys). Needed anyway before an English
version. The SQL error messages are shown to the user as they are (the client does not parse them), so they stay
in the database for now; for an English version they become error codes that the client maps to texts here.
Tests fail if the app uses a text key that does not exist or if a key is unused.

Progress: the mechanism (`src/i18n/`, `tr("key",{params})`) and all notifications and thrown errors in
`main.js` and `crypto-glue.js` are moved. Rounds 2 and 3 moved the privacy and help dialog and the labels, headings and status texts in `main.js`. Round 4 moved the sign-in and key screens (now a normal source file, `app/views.js`, instead of being cut
out of the old base file by `build.py`) and the static page text in `body.html` (written as `{{key}}` and filled
in by `build.py`). Round 5 moved the last texts (figure names, typing line, error prefixes, page title, boot error). A scan of the built page finds no
Norwegian text left outside the language file; the old base file `app/base/messenger.html` had none in the parts that are used.
Step 2 is done.

Step 1 follow-up (2026-10-30): file encryption (`encryptBytes`/`decryptBytes`), the safety number (`safetyNumber`) and the invite
hash (`inviteHash`) moved into `src/crypto.ts`. `main.js` no longer calls `crypto.subtle` at all. New fixtures for them were made
from the old expressions before the move; `tests/img.js` sends an image between two users end to end.

## Step 3 - Backend access layer

One typed module for every Supabase call (tables and `rpc` functions), with types generated from the
database schema. Replaces calls spread around `main.js`.

Progress (2026-10-30): round 1 moved the 15 server-function (`rpc`) calls into `src/api.ts` (`createApi`, one typed function
per database function). `tests/api-unit.js` checks every call against the SQL in `supabase/migrations/` and fails if the app calls
`sb.rpc()` directly. Round 2 moved sign-in and sign-out (`sb.auth`: sign up, password, e-mail code, session, auth-state listener) into the same module; the test
checks the arguments that reach `supabase.auth` and forbids `sb.auth` in the app. `doLogout()` keeps its fallbacks. Next rounds: table calls (`from`), then storage, realtime and the edge function.
The types are written by hand and checked by that test; they are not generated (no Supabase CLI in the build environment).

## Step 4 - State and screens, one at a time

Convert the remaining code to TypeScript piece by piece: state (`S`), friends/requests, chat view,
presence, settings, animations. Order by risk, lowest first. Stop whenever it stops paying off.

## Step 5 - Remove the legacy base files

`app/base/messenger.html` and `old-index.html` are still patched by `build.py`. Once the code they
contain lives in `src/`, delete them and make the build plain.

## Not part of this

No framework, no change in design, no new features, no storage-key rename (that is separate and needs its
own plan because it affects saved keys).

## Risks

- Subtle encoding differences (base64, JSON key order in the fingerprint) -> covered by the vectors.
- Bundler output differing between browsers -> existing browser tests, plus a manual check on the phone.
- Time: Step 1 is small (about a day of work); Step 4 is the long one and optional.
